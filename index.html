📊 핵심 분석 결과 요약

변수 분석(A1~A5)으로 데이터 기반 임계값을 도출하고, AND→OR→최적화 Rule 설계 과정을 거쳐 재현율을 약 4.6배 향상시켰습니다.

📐 평가 지표 정의
Precision (정밀도) = TP / (TP + FP) — 탐지 중 실제 fraud 비율 Recall (재현율) = TP / (TP + FN) — 전체 실제 fraud 중 탐지 비율 False Positives (오탐 건수) — 정상 거래를 fraud로 잘못 탐지한 건수 FPR (오탐률) = FP / (FP + TN) — 정상 거래 중 오탐 비율
※ 이 포트폴리오에서 "오탐 N건"은 FP 건수(False Positives)를, "오탐률"은 FPR을 의미합니다.

① 입회사기 Rule 미포함

join_date가 랜덤 생성되어 가입 직후 fraud 패턴 재현 불가. 실무 데이터에서는 가입 후 일수별 fraud율 분석으로 최적 임계값 도출 가능.

② 카드복제(반복거래) Rule 효과 미미

2,000건 소규모 데이터셋으로 1시간 내 반복 거래 패턴이 충분히 재현되지 않음. 실무 수백만 건 데이터에서는 패턴이 명확히 나타남.

③ 해외이상 Rule 통계적 신뢰도 낮음

국내+해외 동시 사용 사례가 4건으로 통계적 신뢰도 부족. 충분한 데이터 확보 시 더 정확한 임계값(일수) 도출 가능.

④ 전반적 거래 건수 부족

500명 고객 / 2,000건 거래로 실무 대비 규모가 작음. 수백만 건 기준이라면 더 정교한 Rule 설계 및 ML 기반 스코어링 도입 가능.

⑤ Rule 성능 검증의 한계

전체 데이터를 기반으로 임계값별 Precision과 Recall을 비교하여 Rule 기준을 선정함. 현재 성능 지표는 본 데이터셋을 기준으로 산출된 결과이며, 실무에서는 과거 데이터로 Rule을 설계한 후 별도 기간의 데이터에 적용하여 성능 안정성을 추가 검증할 필요가 있음.

✅ 데이터로 증명된 핵심 결론

①타지역 fraud율 100% — synthetic dataset 기준 오탐 0건 — 높은 분리력 확인, 실무에서는 risk signal로 활용
②새벽 1~5시 fraud율 18~28% — 전체 평균(12%) 대비 1.5~2.3배, 시간 조건 유효성 확인
③50만원 임계값 — 정탐률 98.88%, 오탐 2건으로 카드사 환경에서 최적 균형점
④개인 평균 3배 임계값 — 정탐률 100%, 오탐 0건. 절대 금액이 아닌 개인화 탐지의 효과 증명
⑤ATM 채널 제외 — ATM fraud율 0% 확인, 불필요한 오탐 원천 제거

단일 정답은 없습니다. 비즈니스 목표(오탐 최소화 vs 재현율 최대화)에 따라 Rule을 선택해야 하며, 이 포트폴리오는 그 판단의 근거를 데이터로 제시하는 것을 목표로 합니다.

-- customers
CREATE TABLE public.customers (
    customer_id    varchar(10)  PRIMARY KEY,
    age            int4,
    gender         varchar(1),
    city           varchar(20),
    job_type       varchar(20),
    monthly_income int4,
    credit_grade   varchar(2),
    join_date      date

-- fraud_transactions
CREATE TABLE public.fraud_transactions (
    txn_id        varchar(12)  PRIMARY KEY,
    customer_id   varchar(10)  REFERENCES customers(customer_id),
    txn_date      timestamp,
    amount        int4,
    merchant_type varchar(20),
    channel       varchar(10),
    city          varchar(20),
    is_fraud      bool,
    fraud_type    varchar(20)
);
